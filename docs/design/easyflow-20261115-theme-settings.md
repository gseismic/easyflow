## 用户场景与结构

用户在左栏底部进入“设置”，选择白天、黑夜或自动。手动模式立即生效；自动模式按本地时间切换，可调整白天和黑夜的开始时间并保存。外观属于浏览器偏好，页面明确说明存储与时区范围，避免被误认为全实例配置。

```text
左栏：主导航 / 工作流树 / 底部「设置」
设置
  外观：白天 | 黑夜 | 自动                  当前显示的主题
  自动切换时间：白天开始、黑夜开始、保存
  本地存储与时区说明 / 输入错误或保存结果
  告警通知：规划中，后续设置渠道和收件人
```

沿用既有绿色语义与紧凑卡片，模式采用带原生 radio 的可点击选项。设置为低频操作，入口常驻底部，不挤占顶栏监控信息。自动时间非法时给出具体说明，不通过保存掩盖错误。告警部分仅为未来能力的位置，不放可误认为已启用的邮箱发送字段。

## 外观契约

`[假设]` 默认白天，自动区间默认 07:00–19:00。按设备本地时间判断，白天开始包含边界，黑夜开始排除边界；反向区间跨午夜，同一时间不可接受。偏好保存在版本化 localStorage 键中，不含用户名、口令或业务数据，跨标签页同步。

核心为内部模块，统一提供默认值、验证、读写、主题解析与应用；存储失败与非法输入有不同结果，前者允许当前页面应用，后者不修改已有设置。首屏只在 React 挂载后设置主题可能闪白，复制内联时间算法又会漂移，因此选择构建时从同一自包含核心生成初始化脚本，放在字符集和页面元信息之后、应用执行之前，同步根节点与浏览器配色。单元和真实构建均检查该路径。

颜色按表面、正文、边框、焦点、主按钮、状态和代码区域分层，日夜使用同一组语义变量。原生表单和滚动条使用对应 color-scheme；任务图、状态色和错误提示保持含义。自动定时在分钟边界重新读取时间，恢复可见、窗口聚焦和跨标签存储变更时重算；手动模式不保留自动定时器。

## 状态与复核

覆盖：默认值、已保存、自动等待边界、非法/空/相同时间、坏存储、禁用存储、其他标签更新、登录页启动，以及窄屏抽屉和焦点。设置不改变 admin/viewer 的业务权限，未来告警设置的持久化与权限另行设计。

设计已复核：入口不夺取高频工作流位置，时间含义和持久化范围可见，错误提示不伪装成功，后续告警有位置且不承诺已发送。
