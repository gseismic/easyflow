## 场景与现状

用户已指定每个工作流展示 uptime 图、每格半小时、对应错误时间标红。本次在现有页面中实现这一结构。现有工作流列表提供状态、最近运行和搜索过滤，详情提供运行选择、任务依赖和历史；沿用这些入口与配色，不重新设计导航。

- P1：列表中逐个工作流扫视一天的运行时段和错误；详情中查看选定日期的完整时段。
- P2：点选格子查看时间、执行涉及的运行数、错误涉及的运行数，并进入该工作流历史。
- P3：日期选择、前后一天、今天和刷新；沿用现有次要按钮，触发运行仍是详情唯一主操作。
- 现状 tokens：绿色 `#175f42`、正文 `#24362f`、边框 `#e1e9e3`，已有成功、运行中、失败语义色；间距沿用 4/8/16/24px。

结构：`日期与图例 → 每个工作流一行半小时格子 → 点选格子的时间与统计 → 运行历史入口`。详情复用同一组件，位于运行选择卡之前。

用户已确认“列表每行显示，详情展开”。当前时段新增黄色等待状态，帮助区分活跃运行中实际执行与等待调度/依赖/重试；历史等待不完整时不推测补绘。

`[假设]` 首屏以运行时段为主，列表的搜索与筛选收进原生可展开区域；已有搜索或过滤条件时自动展开，原有功能及地址条件继续保留。浏览器验收后压缩了列表上部间距，以便普通笔记本首屏也能看到第一条时间图。

## 时间、颜色与状态

- `[假设]` 默认显示浏览器本地今天，可选择过去日期。起止边界由浏览器本地午夜转换成带时区时间；DST 日自然形成 46/48/50 格，每格始终 30 分钟。
- `[假设]` 绿色表示该格有实际任务执行，蓝色表示该格包含当前仍在执行的任务；灰色表示无执行，浅灰表示未来。红色表示该格发生任务尝试失败或工作流失败，优先级最高。图例和文字详情同时传达语义。
- 黄色表示当前有运行等待执行（排队、依赖或重试等待）。当前优先级为红色、蓝色、黄色、绿色、灰色；过去格子不根据当前等待状态回填。
- 区间为左闭右开 `[start, end)`；零耗时执行作为开始时刻的事件；失败按实际结束时刻归格。logical date、回补业务日期不决定图表位置。
- 聚合 `task_try` 的实际执行区间，避免 clear 和重试等待产生虚假连续运行。没有任何 try 的旧运行才使用 `dag_run.start_date/end_date` 兜底；未开始运行不显示成执行。
- 同一格对 run ID 去重；多次失败可涉及同一运行，不称“错误次数”。重试成功或 clear 不删除已有失败事件。
- 加载显示明确文字；请求失败保留旧图并明确旧数据，支持重试；无活动显示灰格和引导；无工作流沿用列表空态；未来不推测执行。窄屏保持完整时间顺序，通过图表内部横向滚动，按钮支持键盘焦点、文字提示与点选。

## API 与内部接口

新增 `GET /api/workflows/uptime`，使用现有登录保护，viewer 可读。参数为重复的 `dag_id`（1–100 个）、`start_at`、`end_at`（必须带时区）。固定间隔 30 分钟，范围为正的半小时倍数且最多 25 小时；去重工作流 ID，不依赖 DAG 文件是否仍存在。返回统一 UTC 起止时间、服务器 `as_of`、`slot_minutes: 30`，以及每个工作流的格子数组，字段为 `start_at/end_at/state/run_count/failed_run_count`。固定只返回格子摘要，不传出错误堆栈或无限制运行列表。

每格还包含 `waiting_run_count` 和一个示例运行的 `sample_run_id`。出错格子优先携带对应的 `sample_task_id/sample_try_number`；入口通过查询参数定位到失败任务的指定尝试日志，任务当前状态仍展示最近结果，避免重试恢复后误看最新成功日志。同格涉及多个运行时，明确显示运行数，其他运行可继续在工作流历史中查看。

方案比较：前端从最近 100 次运行推图实现短，但会漏高频历史且丢失成功重试前的错误；按工作流逐一请求增加列表开销。选择批量查询与数据库按格聚合，返回规模为工作流数乘格子数。

内部 `queue_task` 返回是否可继续执行：NULL/scheduled/到期 retry 转为 queued，重复 queued 保留时间，运行/终态返回 False；校验暂停、运行状态和 scheduler fence。`start_task_try` 保留已入队时间；旧调用没有入队阶段时以启动时刻兜底。清理仍清空时间，最近尝试的排队耗时不包含依赖等待和 retry delay。

复核：独立新增 GET 不改变原接口；没有对公开 DAG SDK 增加概念。排队时间不能冒充首次创建时间，失败事件不能冒充完整故障持续时间，灰格不能称为服务不可用。以上语义通过 UI 说明和测试固定。
