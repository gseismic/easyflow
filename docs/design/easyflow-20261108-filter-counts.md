# 项目数量与标签操作设计

- 创建时间：2026-11-08 20:22 Asia/Shanghai。
- 创建模型：Codex，基于 GPT-6；环境未提供实际模型 ID。
- 分析范围：基准提交 `552c609bf970792aa50262c888c86df60f39947e` 及已有项目搜索功能的 `WORKTREE`。
- 来源：用户要求实施上一轮围绕项目、标签和运行历史的优化；已有界面采用白底、绿色状态提示、列表与轻量筛选控件。

## 页面和交互

工作流与运行历史继续共享项目和标签选择、分别保存各自的搜索和状态。项目下拉框展示已发现项目总数，每个项目显示匹配数；其他条件生效时展示“当前匹配 / 项目总数”。工作流页的单位是工作流，历史页的单位是运行次数。匹配数受当前页搜索、状态、标签及指定工作流影响，不受当前所选项目或分页影响；总数不受这些筛选条件影响。选中项目后，列表上的总匹配数仍须应用该项目。发现未完成或异常时标明统计不可用或未完成，不能把不完整统计当成零。

标签面板提供“全选当前列表”和“全部不选”；有标签搜索时前者只增加可见项，保留搜索结果外已选标签，后者清空全部选择。没有选择时不限制标签（包括无标签工作流）；选择多个标签时匹配任一标签。全选所有标签会筛出至少有一个普通标签的工作流，与不选择标签的范围可能不同；在面板说明。标签和项目徽标可点击应用对应筛选，标签再次点击可取消。标签面板和项目选择均保留键盘及窄屏可用性。

“重置全部”清除当前页面的搜索、状态、工作流限定以及共享项目和标签；另一页面独立的搜索与状态不受影响。重置必须立即清空仍在输入或防抖中的搜索，不能被旧请求恢复。

工作流详情增加“查看全部运行”，打开精确限定该 DAG ID 的历史，并清除会遮挡结果的已有筛选；历史页显示工作流限定及一键移除入口。从历史详情返回时保留该限定及分页。历史列表显示当前筛选结果总数，继续从全部历史中按原有顺序分页。

## 数据与接口

计数在服务端独立于分页聚合；项目分面按当前条件但忽略当前项目选项计算。总数及分面按当前定义的项目和标签归类，找不到定义的历史归入“项目未知”。工作流与历史使用相同的项目类别和计数结构，项目名与标签仍来自 DAG，不新建项目管理数据库。按当前筛选条件缓存短时间的计算结果并标注统计时间，避免多窗口和频繁刷新反复扫描历史；重新请求不得使用错误条件下的旧结果。记录和调度状态只读，保持现有认证和管理员权限。

面向 Web 的只读接口 `GET /api/workflows/facets` 和 `GET /api/history/runs/facets` 分别接受与列表相同的搜索、状态和多次 `tag` 条件；历史额外接受精确 `dag_id`。响应中的 `groups` 按 `project_kind` 和 `project` 区分项目及特殊类别，每项提供 `total` 和 `matched`；`complete` 标示统计是否完整，`pending` 表示正在发现，`calculated_at` 是带时区的统计时间。客户端用当前项目选择计算展示的匹配总数，不能把 `complete=false` 的结果解释为零。历史列表 `GET /api/history/runs` 的 `dag_id` 为精确匹配，不受分页位置影响。

分面缓存按筛选条件和当前元数据区分，最多保存 16 组，保留 5 秒；同条件并发计算合并。界面每 15 秒刷新统计，打开项目选择时也刷新，发现尚未完成时短间隔重试。数据变更后数字可能暂时滞后，界面显示实际统计时间；列表及运行历史仍独立刷新。

## 自查

- “全选”与“不限标签”不同：前者不包括无普通标签的工作流；文案必须明确。
- 项目数为已发现的不同项目名，未分组、异常和未知是类别而不是项目；不存在可单独创建的空项目实体。
- 统计必须使用分页前的全部记录，项目选项计算要排除项目自身条件；状态过滤必须计入匹配数。
- 同名相似 DAG 的历史不可混入详情入口；返回详情后的范围和游标不能丢失。
- 加载中、发现失败、计数过期和搜索防抖都不能伪装成精确的当前零值；短缓存的计算时间可见。
