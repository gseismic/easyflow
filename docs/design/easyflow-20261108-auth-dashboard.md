## 场景与布局

高频路径为登录 → 首页寻找异常或进行中的工作流 → 选择运行 → 查看任务状态、上下游和日志。管理员可触发、暂停或预览重跑；源码和较少使用的调度参数在详情页按需查看。

首页复用现有列表与绿色主题，顶部显示调度器状态和最后更新；工作流可搜索及按全部、运行中、失败、暂停过滤。每行显示规则、下次计划、最近运行实际状态；没有可信数据时展示未知，不将逻辑时间充当启动时间。

工作流详情包含运行、调度详情和管理员源码；运行区选择一次运行，依赖图叠加对应任务状态，选择节点显示上下游、状态、时间、重试、心跳及日志。空、加载、请求失败、权限不足及长文本均明确展示；节点使用状态文字与图形/颜色共同表达。

## 认证与接口

备选方案：固定密码配置简单但易泄漏；只在前端隐藏操作不能形成安全边界。选择单机 SQLite 账户与服务端会话，管理员和只读用户两种固定角色，通过本机 CLI 建立及重置，避免默认口令；密码使用 Argon2id。会话令牌随机生成且持久化摘要，设置过期和服务端注销；Cookie 为 HttpOnly、SameSite，状态修改需要 CSRF 标记及同源校验，登录尝试受限。只公开登录和静态登录界面；业务 API 默认认证，源码及写操作要求管理员，服务端做最终判断。维持仅本机监听，HTTPS 不在现有服务边界。

现有 Web API 为项目内部接口，增量扩展字段；未经认证返回 401、权限不足返回 403。源码仅从已发现且位于配置 DAG 目录的文件读取，限制大小，不接受客户端任意路径，明确展示当前文件和历史运行版本可能不同。日志可能包含业务敏感内容，只读账户允许读取日志是用户角色选择的一部分。

调度信息调用现有调度计算，候选时间需解释为计划而非执行保证；无计划、暂停和不可确定分别显示。运行时间以状态库实际字段为准。调度器租约更新时间和任务心跳是最近报告，不证明任务一直在推进。

## 设计复核

入口和主路径已与用户先前确认的文字线框一致；结构遵循单机工具，不引入 Airflow 的集群和插件管理。登录与角色、历史源码边界和异常状态由后端强制表达；不改写调度语义。用户实施授权允许在此结构上完成视觉与交互。
