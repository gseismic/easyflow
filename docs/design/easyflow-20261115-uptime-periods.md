## 场景与结构

用户已明确日、周、月均需支持，默认日。沿用列表与详情中的运行时段区域及现有 tokens，仅扩展其周期选择。

- P1：默认查看今天半小时明细，或切到周/月快速找到异常日期。
- P2：点选某天查看执行/失败统计，再“查看当天”返回半小时明细；日志入口继续定位错误尝试。
- P3：前后周期、日期选择、回到今天/本周/本月和刷新。

结构：`常驻搜索筛选 → [日 周 月] 日期与前后周期 / 图例 → 时间图 → 选中格详情 / 查看当天 / 日志入口`。不增加新页面或折叠基础工具。

| 视图 | 范围 | 每格 | 标签 |
| --- | --- | --- | --- |
| 日（默认） | 本地自然日 | 30 分钟 | 小时 |
| 周 | 周一至周日 | 1 个本地自然日 | 日期、星期 |
| 月 | 自然月 | 1 个本地自然日 | 日期 |

`[假设]` 周从周一开始；前后月导航保留所选日并在短月份截到月末。切换视图保留所选日期，按该日期定位对应周/月；回到当前周期使用本地今天。

状态颜色及错误优先级沿用现有定义；一天内发生错误则该日红色，即使重试成功。无执行不等同故障，未来格子不推测结果。空、加载、请求失败保留旧图、键盘和触屏行为继续覆盖；日期格子至少可显示日期，窄屏允许图内滚动。

## API 和聚合

原 `GET /api/workflows/uptime` 新增可选 `granularity=half_hour|day`（默认 `half_hour`）、`timezone`（每日聚合使用，默认 UTC）。旧请求继续限制半小时倍数且不超过 25 小时。

每日聚合要求 `start_at/end_at` 转入指定 IANA 时区后均为午夜，范围为 1–31 个本地日。每个日边界分别转换为 UTC，保留 DST 的 23/25 小时；拒绝非法时区、时间边界和范围。返回 `granularity`、`timezone`；每日聚合的 `slot_minutes` 为 null，半小时模式仍为 30。其他统计、状态和示例失败任务字段保留。

方案比较：逐日调用旧接口增加请求数量；相加半小时计数会重复计算同一运行。选择在已有聚合 SQL 中替换时间格边界，每天对 run ID 直接去重，返回规模最多 100 个工作流乘 31 格。当前等待通过二分查找落入实际日边界，不使用除以固定 24 小时的计算。

复核：API 新参数可选，旧调用兼容；日视图仍遵循原半小时时间语义。周月只是查看范围，每格均为一天，不把本地午夜错误地当成 UTC 午夜。公开 DAG SDK 和数据库结构不变。
