# 项目筛选与即时搜索界面设计

- 创建时间：2026-11-08 19:36 Asia/Shanghai。
- 创建模型：Codex，基于 GPT-6；环境未提供实际模型 ID。
- 分析范围：提交 `552c609bf970792aa50262c888c86df60f39947e` 和本次 `WORKTREE`。

## 现状与目标

工作流列表只对 ID 做浏览器内筛选；运行历史需点击搜索且只匹配工作流 ID。DAG 的 `tags` 已随解析保留，但未在列表展示。用户希望项目入口清晰、搜索少操作、同时保持简洁。沿用已有白底、绿色、状态色、表格和现有组件。

## 信息结构

[假设] 高频路径是选择项目→输入工作流、项目或标签的关键词→结合状态查看记录；项目在工作流与历史之间共享，普通标签为可多选的横向筛选。项目使用 `project:<名称>` 标签表达；其他标签直接展示。

```text
工作流 / 运行历史
项目 [全部 ▾]     搜索 [输入即筛选 ×]       标签 [选择 ▾]   状态 [全部/运行中/失败…]
工作流                    项目       标签             调度/状态
quant_daily_prices        quant      daily · prices   成功
...
                         上一页  第 N 页  下一页
```

下拉项目列表来自完整已发现工作流而非当前页；多标签全部匹配，项目、标签、状态、搜索词之间按与组合。历史结果标注“当前项目”；找不到定义的历史显示“项目未知”，无筛选时依旧可查看。无项目标签显示“未分组”；空或多个不同项目标签显示“项目异常”。

## 交互与状态

搜索等待短暂输入间隔自动更新，不要求点击；输入法组合期间不提交，清空后重置第一页。切换筛选重置分页，进详情和返回时保留筛选。展示加载、请求失败、无匹配、发现未完成和项目异常；状态以文字及颜色共同表达；长名称截断并提供完整文本。移动端筛选自然换行，控件及清空按钮可键盘操作。

## 假设与限制

[假设] 一个工作流只有一个项目，项目不隔离同名 DAG、数据或权限；多个普通标签可同时选择。项目归属从当前 DAG 定义读取，移动项目后历史会按当前项目重新显示；无法发现的 DAG 标为未知，不推断历史归属。旧运行和业务数据不自动修改。
