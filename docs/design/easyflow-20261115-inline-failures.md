## 现状与场景

目标用户在 Web 列表或工作流详情发现红格，希望立即知道哪个任务失败、原始错误是什么、该次日志写了什么。现有页面为常驻搜索筛选、日周月控制、工作流表格和逐行时间图；详情复用时间图。已有样式使用白色卡片、浅绿背景、深绿文字、红色错误、8px 圆角和 8/16/24px 间距，继续复用。

痛点是红格仅提供示例任务和跳转，其他失败项不可见；重试恢复后最新任务信息也不能代表原始错误。A1 已保存红格下方原位展开的方向，本轮承接它的交互，不重画或覆盖图片。

`[假设]` 本轮只实施优先级最高的原位失败排查；其他三项候选建议待评估。`[假设]` 默认选中当前页第一项失败，按失败发生时间从新到旧展示；一个面板只加载一份日志，避免高频工作流产生批量日志请求。

## 页面与信息层级

入口保持列表和详情的时间图，没有新路由或主导航。P1 是失败任务、尝试编号、原始错误摘要与日志预览；P2 是该次时间、当前运行状态及同格其他失败；P3 是翻页、刷新、关闭和查看运行。

结构沿用 A1：

```text
日 / 周 / 月 → 时间格 → 点选红格
  所选时段说明                   [查看当天] [原有运行入口]
  失败详情      N 次运行 · M 条失败记录         [刷新] [收起]
  失败任务 / 尝试列表 | 原始错误类型与摘要
  [上一页 / 下一页]  | 开始 / 结束 / 耗时 / 当前运行状态
                     | 对应失败尝试日志预览
                     | [查看完整日志] [查看运行]
```

唯一主操作为查看完整日志，其他入口采用链接或 subtle 样式。长名称、错误信息和日志在容器内换行；窄屏将列表和详情上下排列。每个新操作的点击高度至少 44px。方向键继续浏览时间格，Enter/空格选择，面板可通过收起或 Esc 关闭，关闭后焦点回到原格子。

| 状态 | 行为 |
| --- | --- |
| 默认 | 红格原位显示当前时段失败列表；切换记录只读取选中尝试 |
| 加载 | 失败列表与日志各自显示加载文案，不显示上一个时段或任务的数据 |
| 空 | 说明记录可能已变化，提供刷新与运行历史入口 |
| 请求错误 | 列表或日志各自提供重试；旧数据如保留必须标明更新失败 |
| 无错误摘要 | 明确原始错误摘要未保存，引导查看日志，不从日志猜测原因 |
| 运行级失败 | 标明该时段没有保存失败任务尝试，提供查看运行，日志区给出原因 |
| 日志不可用 | 说明该次日志未生成或已不可用，仍可看错误摘要/运行 |
| 极端内容 | 列表分页、摘要最多 2000 字符，日志预览最多末尾 12 行且不超过 8000 字符，明确截断；新日志滚动到末尾，使最终错误可见 |
| 切换/关闭 | 旧请求取消；期间无前一条内容串入；切换日周月时重置面板 |

## 只读接口

新增 `GET /api/workflows/uptime/failures`，面向 Web 内部的渐进式排查。必选 `dag_id`、带时区的 `start_at/end_at`，可选 `limit`（默认 25，1–100）、`offset`（默认 0，0 至 2^63−1）。按左闭右开区间查询，正区间不超过 25 小时，覆盖每日格子的 DST 上限；不按 logical_date 过滤，不要求工作流文件仍可解析。

响应包含 `items`、`total`、`failed_run_count`、`next_offset`、UTC 起止时间与 `as_of`。任务项包含 `run_id/task_id/try_number`、该次开始/结束、截取后的 `error_code/error_message`、摘要截断标志、当前 `run_state`；运行级兜底的任务和尝试为空。排序为实际失败时刻降序，再按 run_id、task_id 和 try_number 排序。每次响应使用同一读取快照；分页请求之间不承诺冻结数据库，刷新重新读取当前记录。

查询包含已结束的失败任务尝试及已保存的运行级失败。任务重试和运行清理均保留历史事件。没有独立原因的运行失败在该时段缺少对应任务失败时补充；定义失配有独立原因，与同一时刻、同一原因的失败任务尝试合并。失败运行数按 run_id 去重，失败条目数按实际显示的尝试和运行级事件计数。未来事件不展示，微秒边界保持精度。

认证沿用已有中间件：401 要求登录，viewer/admin 均可读，400 为时间/业务参数错误，422 为声明类型或分页参数错误。未知工作流返回空列表，支持已移除工作流的历史查询。没有写入、路径或 traceback 暴露。日志继续通过 `/api/history/task-log` 读取，显式指定失败 try_number，沿用其目录校验与 1 MB 上限。完整日志链接仍指向已有历史任务页面，该页日志最多展示末尾 1 MB。

## 取舍与复核

按需查询返回红格内的运行与任务，原 uptime 请求及字段保持兼容。运行级失败复用现有审计表，状态库升级时建立时间和运行索引。

复核结果：新接口是读取历史事件，当前运行状态仅作辅助；失败摘要来自已保存的异常而非推断；日志和链接都锁定原始尝试。日期格子的实际 UTC 边界直接沿用响应，不重复推算本地日长；分页与长文本上限明确。复用 A1 结构及既有 tokens，不增加竞相突出的操作或折叠基础筛选。
