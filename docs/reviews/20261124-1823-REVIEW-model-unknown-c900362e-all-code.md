## 原审查验证结果

前端 38 项测试及隔离构建通过。后端全量验证因测试环境磁盘不足和 SQLite I/O 错误未完成。原审查复现了历史任务清理后丢失 XCom、过期 worker 的重试被跳过等行为。

## P1

### R01　拒绝清理当前定义无法重跑的历史任务

修改 DAG 或本地依赖后，Web 仍允许预览并清理旧运行中的成功任务。清理删除 XCom 并重新入队，调度器随后因定义指纹失配直接判失败，任务没有执行。预览和执行应在修改状态前检查定义兼容性。变更定义时，两种请求都应被拒绝，运行状态、任务状态和 XCom 应完整保留。恢复原定义后应能重跑。[清理路由](../../src/easyflow/web/routers/runs.py#L56) · [重跑约定](../../README.md#L20)

### R02　保留已回收任务的重试资格

已领取任务的 worker 续租中断后，执行器把过期尝试置为 `up_for_retry`，却仍跟踪旧进程。旧进程因提交冲突非零退出时，会被误记为 `WORKER_STARTUP_FAILED`，任务跳过剩余重试。应按尝试身份回收进程，让旧尝试退出无法消耗新尝试的重试资格。[本地执行器](../../src/easyflow/_internal/local_executor.py#L133)

## P2

### R03　创建运行前重新校验本地依赖指纹

只修改 DAG 导入的同目录模块时，发现缓存可能仍返回旧快照。创建运行只检查主文件，因此 Web 报触发成功却没有任务执行，定时入口还会占用当期逻辑日期。创建前应校验快照依赖，失配时刷新快照，再由新定义建单。用仅修改依赖文件的场景验证手动与定时入口。[创建运行](../../src/easyflow/_internal/persistent_runner.py#L187) · [创建约定](../design/easyflow-20261108-optimization.md#L45)

### R04　已失败运行的旧队列会阻止清理

在 `A → B` 中，A 成功且 B 已入队后，B 重载变更的源码会导致运行失败，B 却仍处于 `queued`。即使恢复原源码，清理 A 仍持续被 B 阻止。应修正定义失配后旧队列的生命周期，或只用仍可派发的任务阻挡清理。恢复原源码后，清理和重跑应能完成。[清理保护](../../src/easyflow/_internal/state_store.py#L1737)

### R05　批量回补应重查已经满足的跨运行依赖

用 `--max-active-runs 2` 回补含 `depends_on_past=True` 的 DAG 时，第二天可能在第一天完成前返回 `running`。代码用第二天的旧结果结束回补，第三天没有创建。应在同批前序结束后重新推进受依赖阻挡的区间。用不依赖常驻调度器的三天回补验证三条记录都能执行并完成。[批量回补](../../src/easyflow/_internal/scheduler.py#L574)

### R06　任务执行期间应保留已加载的本地模块

DAG 导入本地类后，加载作用域退出时会从 `sys.modules` 移除其模块。任务仍持有类对象，调用 `typing.get_type_hints()` 却无法解析模块内的别名。应让 worker 和 `dags test` 执行期间都能访问这些模块，执行完恢复导入缓存。[导入作用域](../../src/easyflow/_internal/source_imports.py#L109)

### R07　本地 worker 的终止等待没有上限

在 POSIX 上，DAG 导入代码若忽略或延迟处理 `SIGTERM`，启动超时后 `terminate()` 加无期限 `join()` 会被拖住。原审查复现了导入超时后仍执行任务。应给启动超时和关闭路径的等待设置上限，必要时强制结束进程。验证慢导入未执行任务且执行器能退出。[进程等待](../../src/easyflow/_internal/local_executor.py#L102)

### R08　已满容量的 DAG 仍预生成整批补跑日期

常驻调度器串行扫描 DAG。在 `catchup=True` 的 DAG 已达运行容量时，每轮仍先生成最多 1000 个 cron 时刻。原审查测得每个积压的分钟级 DAG 约耗时 0.26 秒，25 个约拖延 6 秒，可能导致后续关闭补跑的高频 DAG 漏调度。应先检查可用容量或按需生成区间，同时在建单事务内保留容量检查。[到期扫描](../../src/easyflow/_internal/scheduler.py#L365)

### R09　过期任务恢复为每个任务申请写锁

本地执行器每轮轮询所有任务，每个任务都单独执行 `BEGIN IMMEDIATE`。用 500 个未启动任务复现了一轮 500 次写事务，实际没有任务可恢复。应先筛选可能过期的运行中任务，再在事务内复核，避免与执行和续租争用 SQLite 写锁。[过期恢复](../../src/easyflow/_internal/state_store.py#L1323)

### R10　运行时段查询逐对匹配执行记录与时间格

用 25 个工作流各每分钟运行一次、共 25.2 万条单任务运行记录查询最近 168 小时，在内存 SQLite 中约耗时 21 秒，超过前端的 15 秒超时。应先确定每条执行区间覆盖的格子，再聚合运行数。验证原规模、格子边界以及一次运行跨多个任务的去重。[运行时段查询](../../src/easyflow/web/uptime.py#L149) · [前端超时](../../web/src/api.js#L56)

### R11　尚未执行任何任务的运行显示为正在执行

实例并发槽满时，DAG 可先被标为 `running`，首个任务却仍在排队且没有尝试。执行时间回退分支把它计入蓝色格，覆盖同格计算出的 `waiting_run_count=1`。应让尚未开始尝试的现代运行显示为等待，并兼容确实缺少任务记录的旧运行。[历史回退](../../src/easyflow/web/uptime.py#L131) · [图例约定](../../README.md#L32)

### R12　序列化 DAG 快照时丢失命名时区

`start_date` 使用提供 `.zone` 而非 `.key` 的动态时区时，快照只保存起始日期当日的 UTC 偏移。纽约冬季起始的每日 09:00 调度在夏季被排到当地 10:00。应保留可识别的 IANA 名称，或明确拒绝无法无损恢复的动态时区。验证冬夏两季的本地钟点。[快照序列化](../../src/easyflow/_internal/dag_parser.py#L403) · [时区约定](../../README.md#L139)

### R13　异步 Python 任务未执行却被标为成功

传入 `async def` 且关闭 XCom 推送时，`PythonOperator.execute()` 返回协程对象，执行器将任务标为成功，函数体从未运行。应等待协程完成或明确拒绝异步任务，覆盖 `dag.test()` 和持久化执行。[PythonOperator](../../src/easyflow/providers/standard/operators/python.py#L25)

## P3

### R14　有限轮询的退出码混入运行的中间状态

`scheduler --max-loops` 可能对同一运行先输出 `running` 再输出 `success`。终态成功时，CLI 仍因中间状态返回 1。应按 `(dag_id, run_id)` 的最后状态和实际调度错误决定退出码，验证重试后成功和真实失败。[CLI 退出码](../../src/easyflow/cli.py#L410)

### R15　清理命令把不存在的运行报告为成功

`tasks clear` 未传 `--task-id` 且误填 `--run-id` 时，空查询结果被当成清理成功，输出 `EXECUTED` 并返回 0。应区分运行不存在和运行存在但无匹配任务。验证预览和执行的错误退出码。[清理命令](../../src/easyflow/cli.py#L324)

### R16　读取正在追加的日志可能超过上限

文件在 `tell()` 后继续增长时，无长度参数的 `read()` 会读到新增内容。原审查复现返回 1,020,000 字节且 `truncated=false`。应使用已采样长度限制实际读取量，并验证追加期间的字节数和截断标志。[日志读取](../../src/easyflow/web/service.py#L834) · [读取上限](../../README.md#L34)

### R17　滚动窗口移出红格时丢失已打开的失败详情

打开最近小时视图最早一格的失败日志后，轮询可让该格滚出窗口。`currentSelection` 随之为空，详情面板卸载，当前尝试选择丢失。应保留打开时的范围和已选尝试，直到用户关闭、改选或离开相应视图。[时间条组件](../../web/src/components/UptimeStrip.jsx#L13) · [滚动窗口设计](../design/easyflow-20261116-rolling-uptime.md#L22)

### R18　历史运行与任务定义可能来自不同版本

打开历史运行后编辑 DAG，若工作流详情轮询先取得新定义，而运行轮询仍保留 `definition_matches=true`，页面会短暂用新定义渲染旧运行任务的依赖。应让任务详情与已确认匹配的定义来自同一份响应，或在渲染前核对两个响应的指纹。[历史运行页面](../../web/src/pages/HistoryRun.jsx#L32) · [历史定义约定](../../README.md#L38)
