## P1（5 项）

### R01　长任务执行期间，同一 DAG 的下一次到期运行被跳过

常驻调度器的 `submit()` 按 DAG ID 检查 `pending`，而 `_run_scheduler_source_once()` 会等待本批运行结束。当任务跨过下一调度周期时，即使 `max_active_runs=2` 且实例并发为 2，第二个到期时刻仍只有一条运行。若 `catchup=False`，等调度器再检查时，中间的时刻还可能被永久跳过。[src/easyflow/_internal/scheduler.py:265](../../src/easyflow/_internal/scheduler.py#L265) · [等待本批运行结束的位置](../../src/easyflow/_internal/scheduler.py#L391)

**修复与验收**　按运行标识去重，让到期扫描可以在已有运行执行期间继续。固定两个相邻的到期时刻，让第一条运行保持执行，确认第二条在第一条结束前创建。重复扫描第二个时刻应只得到同一条运行。

### R02　清理上游后，已入队的下游仍可领取并读取被删除的 XCom

在 `A → B` 中，A 已成功、B 已入队但尚未领取。此时单独清理 A 会删除其 XCom，B 却仍能凭自身的 `queued` 状态开始执行。原审查中 B 因取不到 A 的 `return_value` 失败，随后 A 重跑成功，整次运行仍为失败。[src/easyflow/_internal/state_store.py:889](../../src/easyflow/_internal/state_store.py#L889) · [清理 XCom 的位置](../../src/easyflow/_internal/state_store.py#L1707)

**修复与验收**　在清理时让旧派发失效并重新判定依赖，或在下游已派发时拒绝会破坏输入的清理。按上述顺序领取 B。若接受清理，B 应等 A 重新产出结果后再执行。若拒绝清理，A 的原值应保留，B 仍能成功。

### R03　从本地模块直接导入常量时，旧运行会执行变更后的定义

对于 `from settings import LABEL`，解析结束后全局变量 `LABEL` 是字符串，依赖收集器会跳过它。原审查先用 `LABEL="v1"` 创建运行，只把 `settings.py` 里的值改成 `"v2"`，定义指纹仍匹配，旧运行成功输出了 `v2`。[src/easyflow/_internal/dag_parser.py:509](../../src/easyflow/_internal/dag_parser.py#L509) · [本地加载器计算实际源码摘要的位置](../../src/easyflow/_internal/source_imports.py#L52)

**修复与验收**　记录本次解析实际加载的本地模块及源码摘要，并纳入定义指纹。分别验证依赖未变和仅修改常量的情形。前者应正常运行，后者应在任务执行前识别定义变化。

### R04　过期 worker 的迟到心跳可以重新占用已分配的并发槽

`start_task_try()` 统计容量时会排除已过期租约。续租检查任务状态、尝试编号和 worker 身份，却没有检查原租约的截止时间。实例上限为 1 时，A 到期、B 领取槽位后，A 的迟到心跳仍返回成功，数据库中随即出现两份有效租约。[src/easyflow/_internal/state_store.py:981](../../src/easyflow/_internal/state_store.py#L981) · [领取时的容量判定](../../src/easyflow/_internal/state_store.py#L858)

**修复与验收**　在续租事务内使用与容量统计一致的有效期条件。用固定时钟覆盖到期前、恰好到期和到期后三种心跳。到期前可续租，达到截止时间后旧尝试无法恢复租约，B 已领槽时有效租约数始终为 1。

### R05　普通任务退出码 75 被解释为调度器丢失租约

本地执行器只要看到任一 worker 退出码为 `75`，就终止同批其他 worker 并抛出 `SchedulerLeaseLost`。原审查用单个 Python 任务以该临时失败码退出，在调度器租约有效时也收到“scheduler lease 已丢失”。常驻模式会因此停止其他 DAG 的后续调度。[src/easyflow/_internal/local_executor.py:93](../../src/easyflow/_internal/local_executor.py#L93) · [子进程传递租约丢失的位置](../../src/easyflow/_internal/local_executor.py#L326)

**修复与验收**　通过独立控制信号传递租约丢失，或由父进程核实租约。任务以 `75` 退出时，按其失败或重试策略处理，同批独立任务及其他 DAG 应继续执行。另测调度器真正失去租约的情形，确认调度仍会停止。

### R08　Web 冷启动时把仍在解析的 DAG 报为不存在

### R11　显式清理多个任务时，拼错一个 ID 会造成部分清理
