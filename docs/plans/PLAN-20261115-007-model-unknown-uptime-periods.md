## 目标、边界与依据

按用户要求支持日、周、月查看，默认日视图。日视图保留每格半小时；周视图按周一至周日、月视图按自然月，每格一天。列表和详情一致，可从一天的汇总进入该日明细，错误保留及日志入口继续有效。

当前 API 只接受最多 25 小时、固定半小时格子；当前时间工具和图表刻度均按单日实现。使用现有 React、FastAPI、SQLite 和时区依赖，不增加库，不修改调度或业务数据库结构，不重做 A1，不折叠搜索筛选。

设计见 `docs/design/easyflow-20261115-uptime-periods.md`；沿用 `ui-design-zh`、`api-design-zh`、现有技术栈和 Playwright 验证流程。

## 验收、风险和回滚

- 普通日 48 格，周 7 格，月 28–31 格；默认日，切换与前后跳转准确，单月不会跳过短月份。
- 以浏览器时区的自然日聚合；DST 的日可能为 23/25 小时。错误不被成功覆盖，跨日执行按覆盖日期归格，运行数按 run ID 去重。
- 默认旧 API 行为与限制保留，新增每日聚合限制 1–31 个本地日；拒绝非法时区、非午夜边界及超范围，不返回无限量明细。
- 本次不会更改基础筛选行为、写入业务数据或修改 `GOAL.md`。回滚仅恢复本次代码和对应构建入口。

实施前已复核：不能把每日格子固定为 24 小时；不能通过相加半小时格的运行数生成日统计；当前等待所在格需按实际边界查找。新增选项使用向后兼容默认值，客户端和服务端都覆盖 DST、跨月和非法范围。
