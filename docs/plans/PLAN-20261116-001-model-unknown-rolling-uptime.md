# 最近小时与周月按天展开计划

- 创建时间：2026-11-16 01:32 Asia/Shanghai。
- 模型：Codex（基于 GPT-6；环境未提供完整模型 ID，使用 `model-unknown`）。
- 基准：`9eece2edc1759cb2c8d96675cb0fae8fd22fa260`，开始时工作区干净。
- 来源：用户要求可设置“最近 X 小时”，解决凌晨日视图看不到昨晚记录；补充周/月选中某天后原位展开更紧凑的当天 uptime。

## 范围、依据与契约

列表和工作流详情默认最近 24 小时，小时数可设 1–168 的整数并保存在当前浏览器；保留日/周/月固定日期查看。最近窗口由服务端当前时刻计算，轮询时滚动，跨午夜和 DST 均为实际经过的 X 小时。时间图明确显示起止日期与时间，避免始终标注 +1日。

扩展现有 uptime 只读 API：新增 `lookback_hours`（1–168），与 `start_at/end_at` 及按天聚合互斥。旧绝对范围契约不变。滚动窗口首尾裁剪到真实范围，中间按 UTC 半小时取界，最多 337 格；当前等待为查询时刻快照，放入最后一格。响应带真实起止及 as_of，避免依赖浏览器时钟构造动态 URL。

周/月保留日汇总条；选中非未来日期后，在同卡片下方展开当天半小时图，格子更矮、间距更小。展开图独立加载、错误重试、可收起，不切走原周/月；点击红格沿用失败任务及原始尝试日志。日视图的 DST 23/25 小时语义保持不变。

本轮不增加告警、周期统计、数据库迁移或调度行为，不改 GOAL。采用既有 React/FastAPI、pnpm/uv 工具。
