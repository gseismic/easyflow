## 当前依据与约束

- `GOAL.md` 指明项目希望成为轻量、易用且支持可视化管理任务的 Airflow 类工具。
- README 和 `examples/` 已提供快速开始与场景示例；项目内 `skills/easyflow-usage/` 提供现有使用资料，需要结合当前实现重新核实。
- 测试 DAG 会实际运行任务，启动默认示例目录还可能触发定时工作流；验证应使用仅含教程示例的临时目录和独立状态库。

## 实施步骤

1. 阅读相关源码、命令帮助和界面，确定新手操作路径及限制。
2. 在项目根目录新建独立教程，提供可复制的最小示例和逐步操作。
3. 在临时目录验证示例、关键命令及 Web 的实际运行，复查文档中的链接和说明。
4. 记录验证结果，完成结果文件和计划索引。

## 验证和完成标准

- 教程中的示例能被发现并成功执行；无业务文件或网络副作用。
- 核对命令选项、账号、调度时区、运行状态与常见限制；关键持久化和 Web 操作通过隔离实例验证。
- 教程链接有效，修改经 `git diff --check` 和人工自查。

## 风险与回滚

命令和状态取决于当前工作目录与数据库；教程应明确区分内存测试、持久运行和调度。验证仅使用临时路径。若需回滚，删除本次新增教程、计划及结果文件并撤销本次索引入口即可，不触碰用户数据。

## 实施前自查

避免以仓库示例目录作为首个 Web 演示目录，防止自动执行定时示例；使用独立、仅含手动 DAG 的目录。确认每个命令所用数据库与 DAG 目录一致，并在涉及清理或回补时先展示预览。
