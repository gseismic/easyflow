## 当前状态、设计取舍与约束

- `latest_automated_logical_date()` 把所有 backfill 的最大逻辑时间作为定时游标；它可晚于当前时间，也会越过尚未安排的区间。定时创建还未排除同日已回补的运行。
- 普通运行按 DAG 限额，backfill 按各自 backfill ID 的可选限额；clear 重新激活终态运行时未沿用该规则。
- 自查补充：`create_dag_run()` 可直接创建 backfill，且传入的限额可能与 `backfill` 表记录不同。需要在 DagRun 保存创建时的回补限额；旧运行继续从 `backfill` 表读取，以保持清理容量判断一致。
- clear 的 `task_ids=[]` 因真值判断退化为全选。空列表应返回空结果且不写入状态或审计记录，`None` 继续表示全选。
- 预览与 CLI dry-run 共用无界区间生成并对每个区间打开数据库。预览限制为 1000 个原始区间，超出时明确报错；实际回补创建不施加该预览上限。查询使用单次范围读取，仍以创建时事务重新检查资格。
- 定时游标方案：新增持久化的已扫描回补游标，与已创建的 scheduled 运行时间取最大值；只有调度器扫描到已回补的到期日期才推进。对照方案仅排除 backfill 的最大日期会重复扫描大量已回补区间，或重新创建同日 scheduled 运行。此方案会新增一张 SQLite 表、索引和 DagRun 回补限额列，现有数据库由 `init_db()` 非破坏性扩展。
- 长运行 ID 保留原有短 ID 的 base64 路径；超出单个目录名安全长度时使用固定长度 SHA-256 名。日志写入失败时仍记录任务失败，异常日志可能不可用。

## 实施步骤

1. 修改调度游标与已回补日期查询，在 scheduled 创建事务中排除同日已回补运行；同步 Web 的批量调度状态读取。
2. 按普通运行和 backfill 各自的限额修正 clear；使空列表在预览和执行时返回空结果。
3. 给预览生成增加区间上限，并批量读取各逻辑时间的最新运行状态；确认 Web 统一错误处理对超限返回可理解的 400 错误，更新 README。
4. 为长运行 ID 生成有界日志目录；日志写入出错时仍完成失败状态落库。
5. 添加针对五处风险的回归测试，运行相关与完整测试，检查差异并生成结果文件、更新计划索引。

## 验证与完成标准

- 未来 backfill 不阻止此前 scheduled 区间；已回补日期不重复执行；大量连续已回补日期后仍可继续调度。
- clear 在相互独立的容量下正确重新激活；空任务列表在 Web 预览和清理时不改变任务与 DagRun。
- 超限预览迅速给出明确错误；范围内状态与原资格规则一致，且不逐区间初始化数据库。
- 200 字符运行 ID 可成功执行并记录日志；模拟日志目录不可创建时任务和 DagRun 终结为失败。
- 相关测试与完整测试通过；若必要验证失败先修复，不以失败状态提交。

## 风险、回滚与自查

- 调度游标落库或批量检查若越过未处理日期会造成漏调度：只在对应日期确有 scheduled/backfill 记录时推进，并在容量拒绝处停止；用回归测试验证未来、混合和连续日期。回滚代码可停止使用新增游标表；已有运行记录不删除。
- 预览上限改变超长范围请求的行为：CLI 和 Web 给出明确错误，实际创建维持原能力。超过上限的用户可分段预览。
- 日志目录失败后缺少文件证据：SQLite 的 `task_try` 错误信息仍应保存；不因记录日志失败覆盖原始异常。
- 自查：遵循普通运行与每个 backfill 独立的容量规则；保留预览只读和创建时重检；不修改 `GOAL.md`。环境未提供 `api-design-zh` skill，按项目规则在此记录方案、边界和兼容性取舍。
