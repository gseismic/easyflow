## 目标、范围和边界

1. 使用 DAG 的 `tags` 中 `project:<名称>` 表达单一项目，其他标签可以多个；未指定项目显示“未分组”，多个或空项目标签显示异常并说明，不影响 DAG 调度。已有全局 DAG ID、历史运行和任务记录保持不变。
2. 工作流列表和运行历史支持项目、标签、状态组合筛选，并在页面间保留项目与标签选择；搜索输入自动生效，匹配工作流 ID、描述、项目、标签，历史还匹配运行 ID。支持多关键词、大小写不敏感、中文输入法和清空。所有筛选在服务端分页之前执行。
3. 工作流分页并限制每次昂贵的运行详情计算；历史继续对全部持久化运行分页。历史按当前已发现的工作流归属展示，已移除或暂无法确定的显示“项目未知”，全部历史仍可见；不把当前标签冒充运行时的历史快照。
4. 以两个只手动触发、不写业务文件的新示例展示项目和多标签；严格遵循用户指定的示例命名规范。不得批量修改原有 DAG 文件及其定义哈希，不新增自动运行或覆盖数据。

## 实施步骤

1. 建立并自查页面与接口设计，明确分组冲突、未知状态、筛选语义、分页、中文输入、请求顺序和历史工作流被移除等边界。
2. 服务端构建已发现工作流的精简元数据目录，提供项目和标签选项与轻量调度器状态；工作流服务端筛选、按 DAG ID 稳定分页，只对当前页计算调度详情。历史查询以当前元数据参与服务端筛选，保留缺失 DAG 的全部记录；检查 SQL 参数、排序、大小写和竞争边界。
3. 前端复用现有视觉风格，提供共享项目与标签筛选、状态筛选、即时搜索和清空，正确处理加载、空、错误、冲突、未知、长名称以及窄屏；切换页面和返回详情时保留筛选状态。
4. 添加符合示例命名规范的项目演示和说明；添加覆盖旧历史、无项目、冲突标签、多关键词、组合筛选、分页、大量工作流、并发更新、角色权限和 IME 等实际风险的测试。
5. 按 `review-fix-loop` 反复审查、修复、测试，直到最后一轮没有待修复的逻辑问题且验证通过；执行全量测试、Ruff、构建和隔离浏览器的桌面/手机验证。
6. 不触碰现有业务数据；确认没有排队或运行中的任务后通过 `SIGINT` 平稳更新本机 Web 和调度器，检查认证、历史、项目筛选、调度器与真实浏览器；如不能安全切换则保留服务并报告。

## 验收、风险与回滚

- 无筛选时原有及已移除工作流的所有历史均可逐页访问；项目、标签、状态和各个搜索词同时生效，搜索覆盖数据库中全部页而非当前页。
- 页面快速输入及 IME 组合输入不会让旧请求覆盖新结果；更改筛选回到第一页，往返详情不丢项目与标签。服务端输出为当前已解析的真实数据，发现尚未完成时注明，不能将未知数据伪称为无项目。
- 页面对单次 DAG 计算有上限，项目和标签选项不依赖当前页；必要时以索引和批量状态查询避免随 DAG 数线性建立大量 SQLite 连接。
- 不放宽运行定义哈希、权限或数据路径；不重写既有示例。代码或静态资源可回滚至基准提交，新增非破坏性数据库索引可保留。开发阶段不要求保留旧内部接口，但现有记录和用户数据必须保留。

## 实施前自查

不将项目编码进 DAG ID，避免破坏历史记录。历史筛选必须在分页之前应用，否则旧记录不可找到；来源不明的历史不能被默认为“未分组”。项目标签歧义不应阻止调度，项目显示仅用于组织而不是权限隔离。工作流多时目录选项和调度状态不得依赖浏览器只加载的某一页。
