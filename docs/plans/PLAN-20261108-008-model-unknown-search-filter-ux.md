## 目标与范围

1. 工作流和运行历史分别呈现关键词搜索与项目、标签、状态过滤；搜索和过滤可各自清除，已选条件可见且可单独移除。维持项目和标签在页面间共享、多个标签匹配任一项、所有条件在分页前生效的既有语义。
2. 稳定输入框位置，说明搜索范围和多关键词规则；显示匹配所需的描述及任务信息。新增任务 ID 搜索：工作流匹配当前定义的任务，运行历史匹配该次运行实际保存的任务；不存在历史任务记录时不猜测其定义。
3. 刷新或分享列表地址时保留搜索和过滤；浏览器前进、后退及进入详情再返回不丢失适用的条件。工作流失败过滤明确指最近一次运行失败。
4. 改善小屏幕工作流结果、空状态和后台发现期间的等待体验，沿用当前视觉 tokens。保留旧版静态资源，避免已打开页面请求旧资源失败。
5. 更新说明文档，针对搜索、过滤、分页、历史数据边界和 URL 状态增加必要验证；不改变认证、调度、业务数据库或已有 DAG。

## 设计与取舍

- 高频场景为根据名称或任务定位工作流、按项目和标签缩小范围、查看失败历史。搜索是自由文本，过滤是明确的属性选择；两者可以叠加，但清除操作互不影响。关键词继续兼容项目和标签文本搜索，避免缩减已有能力。
- 页面结构：[搜索输入及搜索范围说明] → [过滤：项目、标签、状态] → [已选过滤条件与清除过滤] → [结果与分页]。搜索清空按钮只清空关键词；清除过滤只清除当前页面状态、共享项目和标签以及历史页面的工作流范围。
- 内部 Web API 继续使用现有 `q` 参数，保留大小写不敏感、多词全部匹配和既有字段；增加任务匹配及用于解释命中结果的可选字段。工作流与历史的任务来源不同，避免历史定义变更造成误报。历史任务匹配使用运行自身的任务记录，在分页和项目统计前应用；控制 SQL 参数与每页返回数量。
- URL 仅保存当前页面的可分享条件，不将分页游标视为稳定地址；无效参数安全回退。已选条件和搜索在详情返回、跨页面导航和中文输入时不能互相覆盖。
- 发现未完成或发生解析错误时不能将部分统计标记为完整；优先缩短待发现状态的刷新间隔，不把旧统计伪装成实时统计。

## 验收、风险及回滚

- 搜索框不会因输入或统计信息变动而明显移动；可区分清除关键词和清除过滤，标签隐藏搜索词不会在清除后残留。
- 工作流当前任务与历史运行实际任务分别可通过 ID 找到；同名任务、已删除工作流、无任务记录、多关键词、过滤组合及跨分页不会串联错误数据。
- URL 输入必须限定合法枚举和长度，特殊字符安全编码；返回链接保留条件，浏览器导航不能被后台状态同步覆盖。
- 窄屏可同时识别工作流和状态；请求错误与发现未完成有明确反馈，不将其展示为准确的零结果。
- 不执行真实任务、不改业务数据；如需回滚可恢复本次源代码与新生成资源，已有历史静态资源和数据库保留。
