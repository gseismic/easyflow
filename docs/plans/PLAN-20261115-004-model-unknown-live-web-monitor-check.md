## 目标与范围

用隔离的 SQLite 状态库和临时 DAG 启动实际 Web 服务及本机 scheduler，从 Web 登录并触发一次包含多个任务的运行，核对调度器在线状态、运行状态、任务状态和日志是否与实际执行过程一致；保留服务运行，供用户打开页面查看。

本次不修改应用代码、不运行仓库内示例、不使用默认 `.easyflow` 数据库、不连接外部服务，也不清理用户数据。

## 当前状态、依据和约束

- README 说明 `easyflow web` 默认启动本机 scheduler，Web 仅监听 `127.0.0.1`，并提供运行、任务详情和日志监控。
- CLI 支持指定 DAG 目录、数据库、日志目录和端口；用户账户与状态库共用数据库。
- 端口 `8790` 当前没有监听进程，工作区干净。
- 按真实 Web 登录和 UI 触发验证；测试账户、数据库、日志和 DAG 均放在专用临时目录。

## 实施步骤

1. 创建临时 DAG 和管理员账户，包含可观察的分阶段任务与日志输出。
2. 在 `127.0.0.1:8790` 启动 Web 和其管理的 scheduler。
3. 用浏览器登录并从 UI 触发任务，运行期间核对运行及任务状态、scheduler 心跳和日志。
4. 等待流程结束，核对终态、各任务结果、运行历史和最终日志；保留服务和临时数据供用户查看。
5. 记录实际观察、验证范围和遗留问题，更新本计划结果及计划索引。

## 验证方式与完成标准

- 浏览器成功访问并登录隔离 Web 实例。
- Web 调度器状态为在线；用户触发的同一 run ID 在数据库/API 和 UI 中一致。
- 运行中看到当前任务运行且后续任务未提前成功；完成后 DAG 与各任务均显示成功。
- 页面日志能看到临时 DAG 输出的阶段标记，运行历史可找到本次运行。
- Web 服务继续运行，最终回复提供 URL、测试账户和保留临时目录位置。

## 风险与回滚

- 仅使用本机回环地址和新的临时状态库，避免接触现有实例或监听外网。
- 完成后不自动停止服务，以保留用户查看窗口；用户查看完后可在服务终端按 `Ctrl+C`，Web 会向其启动的 scheduler 发送 `SIGINT`。
- 临时目录保留；用户查看完成后可删除本次明确报告的临时目录。

使用 `mktemp` 创建新的临时目录，不覆盖既有路径；先确认临时 DAG 可被解析，再启动服务。核对计划范围没有将应用代码改动、默认数据库或外部写入纳入验证。当前没有端口冲突，启动后仍会用 HTTP 和浏览器确认服务实际就绪。
