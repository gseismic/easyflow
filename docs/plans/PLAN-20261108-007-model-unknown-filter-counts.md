## 目标、范围和约束

1. 标签支持全选当前列表、全部不选，默认匹配任一标签，并说明无选择和全选的区别。项目与标签徽标可以直接筛选。
2. 项目下拉显示项目数量、各项目总数及当前筛选命中数；两个页面单位分别为工作流和运行次数，数量覆盖全部分页。发现不完整或统计失败时不能伪称为零。项目仍从 DAG 标签发现，不新增空项目管理或修改已有 DAG。
3. 提供当前页面的完整重置；工作流详情提供按 DAG ID 精确限定的全部历史入口，历史页面显示筛选总数、返回详情后保留范围与分页。
4. 计数按需计算并短时缓存，用户可知统计时间；避免因前端轮询、快速搜索与多用户使后台重复重扫大规模历史。保留认证、现有数据库记录和业务数据。历史时间筛选为后续可选项，不在本次范围。
5. 维持运行中服务，先以独立状态库和浏览器验证；如为使用户测试需要更新本机服务，仅在确认没有排队或运行任务后通过 SIGINT 平稳更新，并核对历史数据。

## 实施步骤

1. 自查计数口径、标签集合、精确 DAG ID、缓存失效、发现异常、组合条件及页面导航；明确不会覆盖上一任务未提交变更。
2. 后端支持任一标签、精确 DAG 历史过滤、工作流和历史项目分面及分页前总数；对同一筛选条件短暂缓存计算结果并暴露统计时间。
3. 前端实现批量选择、数量和统计状态、完整重置、标签/项目快捷筛选、从详情进入指定工作流的全部历史及返回，支持键盘和移动端。
4. 更新用户说明与针对行为风险的自动化测试；进行相关测试、全量测试、Ruff、构建及隔离浏览器验证，包含大量历史、快速输入、缓存、未知项目、分页、认证和精确 DAG 区分。
5. 复查并修复相关问题；完成计划结果文件。确认服务安全后更新用户当前本机服务并验证登录、历史与统计。

## 验收及风险

- 同一个项目在不同项目选择下的分面数一致，统计符合其他条件且不因分页变化；项目未知历史可见，数据和权限不变。
- 全选与清空对隐藏标签的作用明确，无选择包括无标签工作流；更改筛选、返回详情及重置均不会让旧数据或防抖搜索覆盖当前选择。
- 统计结果标明计算时间，缓存限定条件与当前元数据，不跨用户可见权限泄漏；发现不完整时显示未知而不是误导性的零。
- 本次不改运行定义、现有 DAG 示例或自动触发任务；必要时可恢复代码及已生成界面，新增接口和短缓存不迁移或删除数据库记录。

## 实施前自查

已核对项目选择来自 DAG 标签，历史采用当前项目；标签此前为全部匹配，用户已接受改为任一匹配。数量要区分“当前匹配 / 无筛选总数”，且历史项目无运行与删除 DAG 的项目未知必须分开。不同分页和浏览器回退不得改变聚合条件，缓存需避免将已移动项目沿用旧归属。
