## 当前状态、依据与设计取舍

1. `dag_parser.py` 直接编译 DAG 文件，却通过普通 import 加载本地依赖；Python 的同秒同大小 pyc 校验可能继续使用旧代码，随后 `_local_dependency_hashes()` 又读取新文件字节。选择在 DAG 加载范围内使用本地源码 loader，绕过 pyc，记录实际编译字节的摘要；刷新本地模块缓存，避免同一进程再次加载时复用旧模块。复用现有本地依赖范围，排除 easyflow、标准库和第三方运行库。仅调用 `invalidate_caches()` 或删除某个 pyc 无法覆盖模块缓存和加载后文件变化，因此不采用。
2. LocalExecutor 的 `active` 只有本次启动的子进程，`start_task_try()` 只有实例总上限。选择在任务领取的现有写事务中加入单次运行的 `max_active_tasks` 检查；LocalExecutor 同时统计有效遗留任务和待启动进程，容量不足时返回未完成，后续扫描继续。上限沿用项目现有“每个 DagRun”的定义；其他运行仍只共同受实例上限约束。无需修改数据库结构。
3. 回补预览上限为 1000，而输入只能到日期，一分钟调度最小一天有 1440 个区间。选择保留有界预览，扩展开始和结束输入为日期或带时区 ISO datetime；日期继续覆盖 DAG 时区的整日，精确时间按实际时刻比较，起止均包含端点。CLI 预览和创建共用语义；Web 增加精确时间模式，并标明浏览器本地时区。仅提高上限不能覆盖任意 `timedelta` 高频任务，取消上限则恢复无界预览，因此不采用。

## 验证与完成标准

- 预先生成陈旧 pyc 后，同秒等长修改本地依赖，实际执行获得新返回值；记录的摘要来自实际加载源码。加载后依赖变化仍阻止旧运行执行；重复加载和包内传递依赖行为正确。
