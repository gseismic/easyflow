## 目标、范围和边界

1. Web 强制登录；管理员可管理运行、查看源码；只读用户可查看状态、运行、任务与日志。认证和授权由服务端实施，浏览器不可绕过。提供本机 CLI 创建账户及重置密码，首次使用无需内置密码。
2. 首页直观看见调度器状态、工作流、筛选、调度规则、可计算的下一计划时间和最近结果。详情页可切换运行、查看任务状态、上下游、运行时间、心跳、重试和日志；解释逻辑时间和实际时间的区别。
3. 管理员可只读查看已发现 DAG 的当前源码，并明确其与历史运行版本的关系；不假称现有数据含历史源码快照。延续单机、本地监听和现有 DAG 运行、暂停、清理与回补预览能力。
4. 保护已有 SQLite 状态和业务数据，不自动重跑、清理或迁移用户业务数据；保留当前运行服务直到新版本通过验证，重启前检查状态。

## 实施步骤

1. 比较认证和账户初始化方案，建立设计文档；新增账户、服务端会话和权限校验，使用 Argon2id 散列密码及随机会话，限制登录尝试并防范跨站请求；提供账户创建、密码重置 CLI。
2. 扩展只读接口：调度器租约和更新时间、DAG 调度参数及下一候选、每次运行的实际时间与数据区间、任务状态与心跳、依赖关系和当前 DAG 源码。对无法判断、不可用或历史版本变化明确标示。
3. 在现有 React 风格上实现登录、首页筛选与状态、工作流运行/调度/源码视图和任务详情；保留高频操作与异常、空、加载、无权限状态。
4. 更新 README 的账户初始化、使用和限制说明；增加认证/权限/CSRF、旧库兼容、时间和源码边界、真实运行及任务详情等行为测试；执行前端构建、Python 全量测试和 Ruff，并使用浏览器验证两种角色及关键交互。
5. 完成自查，记录结果、索引及遗留事项；在可安全操作时重启现有服务并验证可登录，保留运行状态和业务文件。

## 验证及完成标准

- 未登录请求所有受保护 API 均拒绝；只读用户不能触发、暂停、清理或读取源码，管理员可以；注销、过期、跨站请求和并发尝试遵守约束。
- 空库及包含既有 DAG/运行数据的 SQLite 均能初始化认证且不丢失原数据；不存在固定默认口令；账户数据库中的密码和会话不以可恢复明文持久化。当前测试实例的临时初始凭据是上述明确告知用户的例外。
- 定时、手动、暂停和已结束计划的展示有明确语义；运行的逻辑时间、入队、开始和结束时间不混淆；任务心跳与未知状态如实展示。
- 管理员能查看正确的当前 DAG 文件；越权、目录外路径、文件变化及缺失均有保护或明确反馈；历史运行不冒充当前源码。
- 原操作及示例通过回归；构建和全面测试通过；实际浏览器能使用管理员和只读账户完成场景。

## 风险、回滚与设计自查

- 原系统无认证，升级后首次需要本地创建管理员；CLI 文档、可恢复密码及登录引导须齐全。初始账户创建仅添加认证数据，回滚代码不删旧库。
- 凭证与日志可能含敏感内容；源码只允许管理员，API 一律校验权限，路径限制在 DAG 目录。只读日志需在界面告知访问范围；沿用本地监听，不宣称支持公网部署。
- 计划时间只是候选，不保证准时执行；暂停、手动、未知和已结束等状态不可伪装为下一次运行。状态请求失败不显示“在线”。
- 心跳反映最近报告而不是证明任务内部持续推进；运行定义与当前源码不同须提示，历史无法恢复时如实说明。
- 实施前自查：先加认证保护，所有写操作需显式授权和 CSRF 防护；保留既有运行数据；状态与时间语义以现有调度器为准，不另造第二套执行逻辑。
