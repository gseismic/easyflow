## 目标、范围与假设

新增统一设置页和三种外观模式，自动模式支持自定义白天/黑夜起始时间；完整适配现有工作流、历史、图表、日志、弹窗与登录页。设置页为未来告警渠道与收件人配置保留明确位置，邮件发送本轮不实施；后续事项记录于 TODOS。

`[假设]` 外观为当前浏览器的本地偏好，管理员和只读用户都能设置，不跨设备同步、不改业务权限。为保持现状，默认白天；自动时间默认 07:00/19:00，使用设备本地时间。白天区间为白天起始（含）至黑夜起始（不含），允许跨午夜；两个时间不能相同。模式即时应用并保存，自动时间显式保存。

范围为前端路由、导航、外观状态与共享主题变量、构建首屏初始化、设置页、测试、示例、设计和结果文件。无后端 API、数据库迁移、实际邮件发送、业务运行或 `GOAL.md` 变更。只进行本地 commit，不推送。

## 实施步骤与契约

1. 新增 `#/settings`，左栏底部固定设置入口，窄屏通过既有抽屉访问，保持原有过滤、导航状态和返回路径。
2. 外观核心统一负责三模式、时间验证、存储读取/写入和主题解析。页面启动前的主题初始化与 React 使用同一核心，避免复制时间算法；本地存储禁用、损坏或版本不支持时安全降级。
3. 抽取语义颜色变量并提供白天/黑夜配色，覆盖常用和异常状态；配置原生控件的 color-scheme。自动模式在分钟边界刷新，页面恢复可见、获得焦点和跨标签页配置变更时及时同步，清理定时器与监听器。
4. 设置页提供模式、当前主题、自动切换时间、保存结果及明确的错误/降级说明；告警区域标明规划状态，不展示会误导用户的可用发送开关。

## 实施前自查、风险与回滚

已自查：自动跟随的是用户配置时间，不冒充系统主题；不能只把页面背景变黑而留下白色控件。首屏初始化与运行时应同源，模式/存储变化应取消旧定时；自动与手动模式互切不能重复启动循环。存储失败可在当前页面应用，但不能提示永久保存成功。日/夜时间相等必须拒绝保存，不发送任何报警或业务修改请求。

主要风险为既有硬编码颜色、跨午夜边界、隐藏标签页计时和构建初始化。回滚限定本功能提交，基础界面提交保留；没有数据迁移或业务状态回滚。
