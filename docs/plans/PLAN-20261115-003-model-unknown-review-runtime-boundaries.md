## 目标、范围与约束

消除 LocalExecutor 持有 GIL 导致误判丢失、任务 chdir 导致数据库漂移、非法 executor 留下待执行运行、DAG/任务标识逃逸日志目录、暂存 XCom 可变引用、chain 相邻列表笛卡尔积这六项缺陷。保持轻量单机定位、现有租约与恢复机制、日志读取安全检查及 SDK 调用方式。不改变 GOAL.md，不重构无关代码，不处理已有 Ruff 基线问题。

已读取 GOAL.md、AGENTS.md、KNOWN-ISSUES 索引、既有修复计划和相关实现。六项均有当前代码依据；现有测试缺少对应边界。当前长期问题无本轮六项的主体条目，本轮可解决事项仅在本计划和结果记录。

## 方案及接口复核

使用 review-fix-loop、api-design-zh 和 default-tech-stack-zh。对外调用保持原样；内部接口增加明确的生命周期与身份约束。

- 任务续租：采用独立续租进程，沿用 scheduler 的子进程与管道存活检测模式，覆盖 sequential 和 local。相比仅由 LocalExecutor 主循环续租，该方案也能保护直接顺序执行；相比强制所有任务进子进程，不改变顺序执行的现有进程语义。启动握手成功后才执行任务，续租保留真实 worker PID 和 owner，覆盖结果序列化和提交阶段；异常及进程退出均释放资源。
- 数据库：初始化 SQLiteStateStore 时 resolve 绝对路径，同时生成绝对 SQLite URL，确保重新构造的 worker/续租进程使用同一文件。URL 解析工具的既有相对路径语义保持不变。
- executor：CLI 用枚举约束可选值，并兼容当前 Typer 的 BadParameter 异常；runner、scheduler 和 backfill 的内部入口在任何持久化副作用之前校验。未知值统一抛 ValueError，不能因运行已结束、暂停或无调度区间而跳过校验。
- 日志：DAG、run 和 task 各组件使用带类型前缀的小写十六进制编码，长值回退 SHA-256；不拒绝原先可用的标识。既有日志仍按数据库已存路径读取，无数据迁移。
- XCom：push 当时按既有 JSON 与大小约束保存序列化快照；每次 pull 和提交值读取均反序列化出独立对象，失败尝试不提交暂存值。
- chain：单项到单项、扇出和扇入保持；相邻集合逐项连接，长度不一致在修改依赖前报错。物化一次可迭代参数，避免中间生成器被重复消费；保持 XComArg 支持。

## 实施前自查、风险与回滚

已复核：续租进程不能覆盖 worker PID，父进程死亡必须关闭管道，握手/日志创建/提交失败都需清理；不能在成功序列化前停止续租。路径固定必须覆盖传递给子进程的 URL；日志编码必须限制单个文件名长度且避免前缀碰撞。chain 的中间可迭代参数只能消费一次。executor 校验必须在调度租约、并发配置和运行创建之前。

主要风险为续租进程开销与退出时序、短租约启动窗口，以及改进 XCom 校验时机的可见行为。以真实子进程、崩溃恢复、并发与重试回归验证。无 schema 迁移；必要时仅撤销本轮代码和文档改动，保留运行数据库及用户数据。

## 2026-11-15 03:54 Asia/Shanghai：关联启动缺陷与测试边界复核

- 更新模型：Codex（基于 GPT-6；完整模型 ID 未知）。分析版本为上述基准上的 WORKTREE。
- 真实 LocalExecutor 驱动脚本与 DAG 位于同目录时，`source_imports.py` 会把正在执行的 `__main__` 从 sys.modules 移除，spawn 因 `KeyError: '__main__'` 在执行任务之前失败。它会干扰本轮续租验证，也属于相关进程启动路径；在本轮增加最小修复：刷新本地依赖时保留 `__main__` / `__mp_main__`，并验证模块身份。无其他源码缓存重构。
- GIL 用例将 DAG 放在独立子目录，以单独验证原始续租缺陷；入口模块保留另设回归测试，避免一个测试混淆两个缺陷。
- DAG 构造已禁止斜杠等字符；日志测试使用已允许的 DAG 点名称、长 ASCII 名称及任意任务路径，不扩大 DAG 标识允许范围。
