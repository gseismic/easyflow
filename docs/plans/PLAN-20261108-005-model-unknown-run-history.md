## 目标、范围和边界

在主导航提供独立的运行历史，按入队时间倒序分页浏览当前状态库中的所有工作流运行，包括当前无法发现的工作流。提供工作流名称和运行状态筛选；每条记录能进入独立的运行详情，查看已记录的任务状态、时间和日志。管理员和只读用户均可查看；继续由现有认证中间件保护。

只读取既有运行和任务记录，不新增清理、删除或重跑操作。记录来自当前配置的状态库，不宣称能找回数据库外或已经删除的数据。历史详情不将当前 DAG 定义伪称为历史定义；没有历史快照时明确展示未知。继续沿用原工作流详情及最近 100 次选择器。

## 当前状态与约束

工作流首页只显示最近一次运行；详情调用 `WebService.runs`，最多读取 100 次。任务和日志已有独立运行接口，可在 DAG 不再发现时读取。`dag_run` 由 SQLite 持久化，现有工作流、状态库、业务数据、账户凭据和运行服务必须保留。

## 实施步骤

1. 根据现有页面和设计约束记录栏目、列表、详情及各状态的结构；复用现有导航、字体、颜色和组件。
2. 为全局历史提供带上界的查询接口，以入队时间、工作流 ID 和运行 ID 组成稳定游标，避免新记录写入时翻页漏掉既有记录。提供状态和工作流筛选，新增查询索引兼容既有状态库。
3. 实现导航、分页列表和独立运行详情，复用现有状态、时间、任务和日志组件；处理工作流已移除、长文本、空记录、加载和请求错误。
4. 更新使用说明，增加身份鉴权、超过 100 条、同时间戳、翻页期间新记录、筛选、旧库、工作流移除后详情和日志等测试；执行相关及全量测试、Ruff、前端构建和浏览器验证。
5. 自查并记录结果；确认无运行中的任务后平稳重启本机服务，复验真实数据与原有记录。若有正在执行的任务，避免中断并如实报告。

## 验证与完成标准

- 已登录的管理员和只读用户均能访问列表及运行详情，匿名用户不能；现有管理权限不降低。
- 超过 100 条、相同入队时间、多个工作流及工作流文件不再存在时，记录仍能按页访问；翻页时新增较新记录不导致已存在的旧记录被跳过。
- 独立运行详情展示相应运行的任务状态与日志；定义或日志不可用时如实提示。
- 保留旧数据和行为；构建、测试及浏览器桌面和移动视图验证通过。

## 设计自查、风险和回滚

- 已比较偏移分页与稳定游标：运行可随时增加，偏移分页容易重复或漏掉旧记录，因此选择基于固定排序字段的游标。每页只拉取有限数据，状态和工作流筛选在服务端执行。
- `queued_at` 为已有入队时间；同一时间用 DAG ID 和运行 ID 打破并列。筛选变化时从第一页重新开始，显示时间采用浏览器本地时区。
- 历史任务定义没有快照，详情仅展示已记录数据；当前 DAG 不存在时不得影响历史列表或历史任务日志。
- 现有 SQLite 表仅增加可重建的索引，不删除、更改历史行；回滚代码后索引可无害保留。保留原静态资源构建流程；重启不使用已知会遗留调度器的 `SIGTERM` 路径。
