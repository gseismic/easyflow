## 目标与范围

修正评审确认的高频 API 和行为差异，补齐单机调度与最小可视化管理闭环；以 Airflow 3.2 公共接口和明确标注的子集为对照。保持单机、SQLite、少概念和渐进复杂。设计取舍及待确定项见 `docs/design/easyflow-20261108-optimization.md`。

范围包括：TaskFlow 与传统 Operator 的 XCom/依赖、`default_args`、Context、BashOperator、DAG 自动发现、DAG 解析隔离、调度时间与兼容迁移、调度并发及容量、代码版本承诺、回补预览、DAG 暂停/恢复、运行历史及日志、最小可视化界面，以及相关文档和验证。

2026-11-08 更新：用户要求 CLI 使用 Typer 以简化实现。本次将现有 argparse 命令整体转换为 Typer 命令组，并一并覆盖 Web 入口；复用核心执行函数和错误语义，不额外维护两套解析器。

不实现分布式 Worker、多用户权限体系、完整 Airflow Provider/插件生态、动态任务映射和完整 Airflow CLI/REST API；不修改 `GOAL.md`。用户已明确当前开发阶段无需保持既有 easyflow 的行为或数据库兼容，因此不设计旧版迁移或兼容层，也不删除现有用户数据。不为压缩代码量牺牲状态安全、外部副作用提示或明确错误。

## 当前状态与约束

- 上一轮复现了接口参数静默忽略、数据依赖丢失、自动发现遗漏、cron 语义差异、DAG 导入退出进程、跨 DAG 调度阻塞、并发上限范围不符和代码哈希范围不足。
- 当前 `pytest` 基线为 87 项通过；现有结果不覆盖上述全部缺口。
- 用户已选择本机浏览器 Web 界面、Airflow 3.2 默认时间语义，并进一步明确当前开发阶段不必考虑既有 easyflow 的兼容性。已有数据库不自动删除；旧版本数据是否可直接使用不作承诺。
- 用户已确认 DAG 列表和 DAG 详情两层结构，满足 `ui-design-zh` 的结构确认要求。
- DAG 执行会产生外部副作用；不声称调度器能对任意外部系统提供 exactly-once。

## 实施步骤

1. 核对 Airflow 3.2 官方接口、既有实现和测试，明确支持范围、默认值、迁移边界及错误语义；完成设计自查。
2. 修复高频公共 API：严格处理 `default_args`；统一 XCom 引用的依赖收集及运行时解析；对齐支持范围内的 Context 和 Bash 行为；为每项真实风险添加行为测试。
3. 修复自动 DAG 注册与发现；设计并实现能够隔离导入退出和超时的解析边界，不重复执行已被判定为不安全的解析。
4. 重构调度推进与并发计量，确保多个 DAG 能独立推进，所有执行入口共享明确的容量契约；保留并验证租约、恢复和 SQLite 原子性。
5. 按用户选择实现 Airflow 3.2 默认时间语义；修正版本哈希承诺并处理依赖变化；补充安全的回补预览和恢复路径。
6. 增加 DAG 暂停/恢复和运行、任务、日志查询；实现结构确认后的最小可视化管理界面，并覆盖空、加载、错误及较长内容状态。
7. 合并可共享的执行逻辑，避免为兼容不同入口复制状态机；更新 README、支持边界和设计文档，说明时间及数据库行为变化。
8. 执行针对性测试、完整测试、前端构建及适当的真实运行检查；检查工作区并完成自查，生成对应结果文件和更新索引。
9. 按用户要求将 CLI 命令解析统一为 Typer，核对帮助、退出码和主要命令的实际使用。

## 验证与完成标准

- 已承诺的受支持 Airflow 示例能运行且结果、依赖、状态及时间语义符合明确基线；未支持能力在合理边界明确失败，不静默忽略。
- 两个独立 DAG 在容量允许时可同时推进，超额跨入口执行受到限制；任务和 scheduler 故障后仍可按既有约束恢复。
- 数据库与时间语义以新设计为准，不承诺旧数据可直接使用；回补和清理提供可检查的影响范围。
- 界面可查 DAG、运行、任务和日志，可触发、暂停/恢复及安全重跑；关键异常状态可理解、可恢复。
- 运行相关回归测试和完整测试；涉及 UI 时验证构建及关键交互。无法运行的检查须记录原因和影响，不报告为通过。
- 与设计承诺不符的遗留事项按项目规则记录，不因测试通过就宣称全部兼容。

## 风险、回滚与计划自查

- 时间语义和数据库结构变化可能影响历史任务：按用户要求不构建迁移层，开发和验证使用临时数据库；保留现有数据并在交付时明确新旧行为边界。
- 并发及解析隔离可能引入进程、序列化或租约竞态：优先复用现有事务与本机锁，覆盖不同执行入口、超时和进程退出。
- UI 带来依赖和维护成本：限定单机高频闭环，保持组件与服务边界简单；不构建完整平台。
- 自查：已区分用户接口与内部协议，保留持久化和外部幂等约束；时间语义与 UI 形式已由用户确定。实施范围变化时先更新本计划。
