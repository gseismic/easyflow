## 目标与范围

恢复已安装的 `easyflow --help`，让项目安装时选用可正常显示帮助的 Typer。工作范围限于 Typer 依赖声明、锁文件、帮助回归测试及用户当前的 Miniconda 安装。

## 现状与依据

`pyproject.toml` 允许 Typer 0.15。Miniconda 中的 Typer 0.15.1 在生成帮助时无参调用 `make_metavar()`，Click 8.3.0 的方法需要 `ctx`，主命令因此退出 1。项目环境锁定的 Typer 0.28.0 可以正常显示主命令和子命令帮助。

Typer 从 0.26.0 起内置 Click。`src/easyflow/cli.py` 使用 Typer 的公开接口，可以在验证后以该版本作为依赖下限，避免帮助受外部 Click 版本影响。[Typer 0.26.0 发布说明](https://typer.tiangolo.com/release-notes/#0260-2026-05-26)

## 实施与验收

1. 补充主命令、命令组及带位置参数的子命令的帮助回归测试，确认旧环境能复现错误。
2. 在临时目录验证 Typer 0.26.0，再更新项目依赖声明和锁文件。核对锁文件差异，运行后端测试和修改文件的静态检查。
3. 核对 Miniconda 中已安装包的 Typer 版本约束，预览安装差异，再将当前安装同步到已验证的锁定版本。验证 PATH 上的 `easyflow` 主命令和各子命令帮助均返回 0，并核对依赖检查结果。

## 风险与回滚

Miniconda 由多个工具共享，Typer 内部接口变化可能影响依赖它的其他 CLI。安装前记录现有依赖检查结果，并用隔离加载验证版本兼容性及常用入口。如果升级引入回归，可恢复原 Typer 版本和 easyflow 的可编辑安装，把项目环境用于验证修复。仓库内的依赖和测试改动可按基准提交核对和撤销。

实施前已自查锁文件、实际命令入口和 PyPI 安装声明，验收覆盖出错的已安装入口以及项目声明的最低版本。
